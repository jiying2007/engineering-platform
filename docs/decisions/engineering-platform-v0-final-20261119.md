# Engineering Platform｜账号级开发会话历史综合终版

**版本：Final 1.3（账号级相关会话复审）**　 **日期：2026-11-19**  
**适用：个人及 2–8 人可信研发团队；Windows Terminal／SSH／Ubuntu；现有 Codex CLI、Claude CLI、ADK、GitHub/GitLab、飞书项目／TAPD。**  
**性质：唯一维护的工程工具和实际研发工作流决策。不是当前账号已获模型额度授权、已部署服务器或产品通过验收的证明。**

## 一、最终决定

**日常开发不依赖 `eng`。** 使用真实已安装并获得批准的原生 Codex CLI／其他编码 CLI + 现有 ADK Skills + 项目工具链。`codex-tui` 仅为 Codex 会话观察、待处理路由和 Git/Forge 上下文的可选界面；不拥有独立 Agent、任务队列或恢复权威。代码和 CI 归 Git/GitHub/GitLab；产品与 QA 的需求、缺陷、复测和关闭归飞书项目或 TAPD；KWS/Audio 的数据、训练和评估归各自项目事件驱动系统；固件与运动控制归项目工具链、设备、供应商和 QA 实测。

**`eng V0` 暂不进入生产默认路径。** 只有实际量化证明其 Git worktree／diff／日志辅助能比“原生 CLI + Git”减少负担时才保留。PR #311 的模型包装式 V0 暂停生产准入；不因已写完代码或通过无模型 CI 就必须合并。

**现行额度禁令不变：未经明确新授权，不消耗 Codex CLI／Cloud／ChatGPT Work 共享模型额度。** 允许的无模型检查（CLI 版本、帮助、登录状态、Git、PR/CI、测试及静态分析）不等于允许新模型回合。独立 Relay／中转站仅在真实身份、端点、模型、计费、权限与隐私被批准并核验后才可调用，绝不静默兜底或切换。

**去中心化不是无流程**：一项任务只保留其已有的业务/科研/仓库权威以及必需的执行与验证证据；不要复制第二个工单、第二套 Agent 会话、第二个团队数据库、第二套科研调度器。

## 三、日常工作如何实际运行

### A. 产品／QA 缺陷与功能（PCR02、Linux、MCU、普通代码）

**飞书项目或 TAPD 原工单 → 研发人员授权读取与澄清 → 原生、已获准 CLI／手工开发 → 真实项目构建/单测 → Git PR/MR 与 CI → 产物/固件/设备验证（按需） → 产品与 QA 回原工单复测并关闭。**

原工单 ID、现象/复现、代码范围、验收条件和保密级别进入研发输入；PR/MR 仅关联允许公开的工单身份，不复制企业私有附件。若工单材料不全，先在原系统澄清而不是自行伪造需求。GitHub Issue 只保留仓库内部技术工作，不充当第二份正式业务工单。

### B. 真实算法研发（KWS、Audio、AEC）

**研究目标／数据来源 → 原仓事件驱动流水线 → 实际生成/训练/评估 → 独立来源与测试锁定 → 数据/模型/资源/音质结论。** 事件完成后才触发下一阶段，既有缓存与审核数据必须复用；不创建按小时巡检、无音频准备循环或自动多模型付费回合。具体质量评价与部署由 KWS/Audio 项目定义，不由 eng 自行宣布。

### C. 工程工具（ADK、Safe、codex-review-service、codex-tui）

技术问题以对应仓库为权威。原生 CLI（仅在有授权时）或手工修复 → 受保护 PR/MR → 真实 CI → 精确 main 核验。审查服务继续按自身 GitLab 事件机制运行，ADK Skills 使用既有来源及版本规则；不通过 eng 另建团队审核/发布调度器。GitLab 多实例接入和服务部署仍由独立项目负责。

### D. 个人、团队与供应商协作

个人默认 **Windows Terminal → SSH → Ubuntu Git 仓库 → 当前原生 CLI**；需要多会话导航时可选 `codex-tui`。团队每个人保留自己的 OS 用户、CLI 登录与模型费用归属，通过 `AGENTS.md`、项目脚本、Git/PR/CI 和飞书/TAPD 协作。共享 Ubuntu 上的同 UID 不构成隔离；供应商交付、设备校准、硬件变更通知和生产刷机按独立审批与测试流程进行。只有真实并发需求才考虑队列；不建立统一团队 Agent 服务。

## 四、Codex CLI 与费用：历史可用，不代表现在准入

当前只允许在目标开发主机做**无模型且不会启动 turn** 的观察：

```bash
type -a codex
codex --version
codex login status
codex exec --help
git status --short --branch
git rev-parse --show-toplevel
# 使用对应 Forge 的人员按需查看 gh/glab 登录状态
```

`codex login status` 只能检查该 CLI 感知的本地登录状态，不能证明当前具体模型可用、预算获准或隐私合约满足。过去 `priority/Fast` 运行时体验亦不能反向推导现在可以付费执行。保留历史 `CODEX_HOME` 用法，不复制密钥文件，也不把 CLI 版本固定为 0.146.0、0.157.1 或某个团队通用版本。

**执行通道必须三轴分离**：Provider/模型身份、Credential/费用归属、Execution/实际主机+CLI+命令+仓库。现在的 ChatGPT 登录路线仍受 Codex/Work 共享额度禁令限制；未独立验证的 Relay、中转站、OpenCode 或其他客户端不能当作自动替代。当且仅当通道已经获得新的明确授权、真实可用并符合成本及安全要求时，才允许该通道启动模型回合，不做静默 fallback，也不将未知用量写成零。

## 五、eng 的精简边界与去留

**日常入口不应要求安装或运行 eng。** 原生 Codex CLI 已有会话、执行、审批与原生工作区能力；`codex-tui` 已定位为薄观察面，故 eng 不应新增另一套 Session/Run/Queue/Provider、组织工单或科研实验账本。若比较后确有收益，eng 仅保留低风险、确定性的 Git worktree、diff、检查日志汇总，且不代替原生模型调用。

**当前 PR #311 尚不可生产合并为默认执行器**：其禁用 `codex` 程序名的策略不具备真实费用判定能力；OpenCode 示例未在目标主机核验；跨 `ENG_HOME` 仓库互斥、监督进程被强制杀死后的身份和防盲重放、`git add -A` 对未知敏感新文件的风险尚需修复。与其补出第二个高复杂度执行引擎，应先证明原生 CLI 的真正缺口。不能证明收益则关闭模型包装方向，仅保留静态辅助或直接退役 eng。

## 六、按事实放行，不再叠加平台工作

| 验收关口 | 必须实际留下的结果 | 没有结果时的判断 |
|---|---|---|
| 0. 目标主机现状 | 当前 `type -a codex`、CLI/登录状态、项目环境、ADK 版本/来源、Git/Forge 状态（无模型） | 只能说明历史可用，不能宣称当前可用 |
| 1. 授权的执行通道 | 一条获准的模型、凭据/计费与真实 Execution 路线；明确隐私、沙盒、停止和用量证据 | 继续禁用模型回合，不创设后台准备巡检 |
| 2. 代码真实任务 | 原工单或真实技术需求，真实变更 commit、项目检查与 CI、失败现场及 PR/MR | 测试模拟、文档或绿色 CI 不等于研发结果 |
| 3. 领域闭环 | KWS 的训练/锁测/资源，Audio 的声学指标与独立来源，MCU/FOC 的目标板/设备结果，产品 QA 原工单复测 | 不以其他领域通过替代当前领域验收 |
| 4. 团队试用 | 至少两个实际研发仓库、约五个低风险任务；团队场景每人独立账号；记录实际人工步骤、耗时、调用费用（若可得） | 未观察收益不扩建统一平台 |
| 5. 退役旧架构 | 旧主机进程/外部未知任务核验，保留 Git/Issue/PR、必要 Actions 制品/日志；受保护 PR 清退旧服务和 CI；最终核验 `digital-worker` 仓库确已删除 | 不把提供脚本/历史备份写成永久删除或生产退出 |

**停止条件**：如果真实工作仍卡在模型登录/费用、设备、数据准入、GitLab 权限、供应商或 QA，优先修对应责任系统的实际问题；不要为了“让平台落地”扩展 eng/TUI/管理服务。如果工具没有减少真实研发工作的人为步骤或恢复时间，就不应继续扩大范围。

## 七、当前仓库状态与归档原则

截至 2026-11-19 本轮复核：`engineering-platform main = 2f75e1e9…`；V0 PR #311 仍开放；归档决策 PR #312 在分支上，不能在合并前称其进入受保护 main。`digital-worker` GitHub 仓库仍存在，不能把退出准备说成完成。原项目 KWS/Audio、ADK、Safe 系列的测试结果各自有效，但不能把历史 PR 通过推导为当前设备/模型/生产资格。

**唯一方案源**：更新现有 `engineering-platform/docs/decisions/engineering-platform-v0-final-20261119.md`，不再建立平行的方案版本；同名 Word 作为可下载阅读快照。方案修订不能启动模型、不触及企业私密账号，也不自动创建巡检。

**账号历史说明**：此方案基于可检索到的相关账号会话、此前用户终端回执、已连接仓库与已归档资料。部分旧结论为助手生成的阶段报告，需由对应原始 Git/CI/主机回执再次确认；不宣称逐条访问了账号所有历史消息，也不凭单次检索保证覆盖所有会话。历史执行不等于当前授权。

**一句话终态**：**让原生已批准 CLI 做真实开发，让各项目现有自动化做持续研发，让 Git/CI 和产品/QA/设备记录证明交付；codex-tui 只辅助观察，eng 只有在确有明确净收益时才保留。**
