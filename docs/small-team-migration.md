# 切换到个人和小团队工具

本页适用于从原 Core/Worker/Action Gateway/PostgreSQL 部署切换到 `tool/` 下的 `eng`。新工具使用独立本地数据目录与 SQLite，不双写旧数据库，不加载旧服务状态，也不保留兼容运行层。

仓库保留旧代码、回执和文档供查证。保留不表示需要继续部署这些服务，也不表示原生产资格、设备验证或未知外部操作已经解决。普通新用户直接使用新工具，无需先部署或迁移旧系统。

## 切换前确认实际运行位置

1. 列出真正运行旧服务的主机、OS 用户、启动方式、仓库和数据路径。记录旧二进制/commit、schema 版本、数据库和产物位置。
2. 盘点活动 Run、模型进程、设备操作、push/PR 和结果未知的外部调用，保留各自精确身份与最后观察。
3. 在已确认的旧部署中停止接收新任务。等待正在执行的任务完成，或按原有停止流程结束进程并核对结果。
4. 核对仍存活或无法确认停止的执行；未解决前不让新工具接管同一工作区、仓库或设备。

上述动作必须针对实际旧主机实施。本仓没有访问未知主机的能力；下载或安装新工具不会停止旧服务，不应根据仓库里存在部署文件推断现场已经迁移。

## 保留旧事实

- 使用旧数据库支持的一致性导出/备份方式，保存 schema 版本和恢复说明；备份真实使用的数据库，不以配置样例代替。
- 保存产物、日志和索引，保留原 Work/Run、commit、PR、回执和 digest。
- 记录未知结果及后续核对方式。一次查询没有发现 PR，不能推导旧发布调用从未发生。
- 不把原 UNKNOWN 或未完成项批量改成已取消、未执行或已解决，也不重跑历史试点来制造新的通过结果。

这些档案按原版本和任务范围只读保存。若需继续旧工作，在原项目记录中关联历史材料，再建立新工具任务；新任务只承接明确可继续的步骤。

## 按项目接入新工具

1. 使用新 data-dir，放在执行主机本地磁盘；不要指向旧 PostgreSQL 目录、共享 NFS/SMB 或原工作区。
2. 登记费用来源明确、已获准使用的 Runtime，以及项目基线、实际构建/测试命令和所需产物。
3. 先运行发行包的无模型例子，检查安装、工作区、日志和停止路径。它只验证工具行为。
4. 选择一个低风险真实项目任务，在独立 worktree 上完成修改和约定检查；保留未验证项。涉及设备行为时补充真实设备结果，或由责任人明确缩小交付范围。
5. 确认新路径能减少准备、结果整理或恢复负担后，再切换其它项目并退出旧运行服务。

个人和可信小团队可以沿用终端、SSH 和现有 Git 平台。需要成员间源码/凭据隔离时采用各自实例；共享 worktree 与同 UID 不是安全隔离。`eng` 执行账号不应持有不必要的 Git 发布凭据，成员可在自己的工作机继续发布。

## 新工具备份与恢复

使用 `eng --data-dir ORIGINAL_PATH backup NEW_DIRECTORY` 创建离线备份。先停止接收任务和 `serve`，确认所有本机执行进程结束；备份入口取得调度锁并再次核对。备份目录必须尚不存在，不能只复制 live `eng.db` 主文件。

备份包含一致性 SQLite 快照、项目与 Runtime 登记、任务 worktree、日志、产物，以及路径、文件类型和摘要清单。符号链接保留为链接，不复制目标。原 Git 主仓库、外部工具链和 Runtime 私有凭据另行备份；备份内的 worktree `.git` 仍指向原主仓库。

这条恢复路径仅支持同机原路径灾难恢复，不是将仓库和任务搬到另一台机器。恢复前停止原实例，确认原进程结束，将当前 data-dir 移到独立保留位置；目标路径必须不存在。使用匹配版本执行：

```text
eng --data-dir ORIGINAL_PATH restore BACKUP_DIRECTORY
eng --data-dir ORIGINAL_PATH recover
eng --data-dir ORIGINAL_PATH status
```

工具校验清单后恢复文件；旧排队任务保持待核对，不自动执行。核对原主仓库、worktree 引用和外部操作事实后，再对明确可以继续的任务 `resume`。不要将备份中的 `.git` 指针当作已可跨目录迁移的仓库，也不要在原进程仍运行时恢复第二份状态。

即使数据库回到了早期状态，旧模型调用、提交和远端操作也不会因此撤销。备份后出现的新记录和未确认事实应保留并逐项核对，不能以恢复后的状态抹去它们。

升级前使用同样流程备份。新版本尚未运行任务时，可以恢复匹配的二进制和完整备份；一旦运行过任务，先保留新版本状态并核对新增事实。不得让旧二进制直接写不兼容的新数据库。

## 明确保留的边界

- 不改写旧生产资格。新的范围可以替代原规划，但“暂不计划”与“技术问题已修复”分别记录。
- 不复制第二套 Issue、PR、审查或知识台账；项目仍拥有业务接受和发布事实。
- 不为迁移扩大模型额度授权；原有 Codex/ChatGPT Work 共享额度限制继续适用。
- 不强制采用 digital-worker。其三类模板和历史参考按需使用，ADK 的已有方法继续复用。
- 不自动删除失败现场、未知结果或历史证据。清理只针对明确归属、已保留结果且获准清理的目录。
